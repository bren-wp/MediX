# MediX v0.3.19 — startup stability and memory optimizations

This Android follow-up reduces work on the first rendered frame, avoids redundant catalog allocations and prevents a slow native reminder provider from blocking the medicine UI.

- Defer creating the Search, Therapy, Favorites and More tabs until opened; retain visited tab state.
- Precompute normalized candidate fields once when linking HALMED/HZZO and official wholesale catalogs. All exact ingredient, strength, counted pack, ATC and ambiguity checks remain mandatory.
- Compile catalog identity regexes once rather than thousands of times.
- Avoid copying decoded string-keyed JSON maps for each official record.
- Do not await native local notification initialization before displaying browsing/navigation; a missing notification provider does not crash permission requests.
- Add widget coverage for lazy tabs and a never-resolving native reminder service, regression coverage for many same-brand formulations and a CI diagnostic measurement for the actual offline catalog loader.

Version: **0.3.19+22**.

Release only after Flutter analyze/tests, real official catalog validation, Dart reachability audit, debug APK and release APK/AAB pass on the latest commit; then verify public release assets and SHA-256 hashes.

No runtime speedup percentage or physical-device crash resolution is claimed without on-device measurements and logcat evidence.
