# MediX v0.3.18 — Android startup stability hotfix

This release focuses on the reported long medicine database loading times and application freezes/crashes.

- Official HALMED, HZZO and wholesale JSON catalogs are read as bytes and processed off the main Flutter/UI isolate.
- Large source bytes use transferable buffers instead of being decoded and parsed synchronously on the UI thread.
- Cross-catalog matching uses a read-only HALMED trade-name prefix index built once per load rather than checking every medicine for each of thousands of source records.
- All existing strict active-ingredient, strength, package, ATC, ambiguity and published-price safety checks remain in place.
- Existing failure and retry screens remain available for invalid source data or exceptions; no new network dependencies or permissions.
- Added regression tests for exact matching in a large catalog and an end-to-end load of the real bundled offline JSON assets.

Version: **0.3.18+21**.

**Release gates:** Flutter analysis, full tests including real catalog loader, bundled data validation, dead-code audit, Android debug build, release APK and AAB. A GitHub release is only confirmed when its public artifacts and version tag are verified after merging.

Note: CI cannot by itself prove the absence of device-specific crashes or provide physical-device timing metrics. A logcat trace remains necessary if problems persist.
